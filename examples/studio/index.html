A guided run of examples/glm_openrouter_agent.py. The left column runs each step. The panels on the right show what the database did.

loading

1Brief the assistant

A graph memory stores three things: entities such as people, projects and services; edges between entities, for example Ada leads Project Kestrel; and facts, each attached to the entities it is about. This step deletes the database and writes the day-one briefing: four edges and five facts, all with writer onboarding and the episode Team onboarding doc, 2026-03-01.

2Ask the two-hop question

The question is: Ada's project is paging. Who should I wake up, and why? No stored sentence contains both Ada and paging, and Bo is not named in the question. Text search only finds what shares words with the query, and a vector store only finds what is similar to it; neither follows a chain of facts. The graph arm walks Ada to Project Kestrel to ingest-service to Bo and returns every fact attached to the entities it reaches. The walk is drawn in the graph panel as it runs.

3The world changes

Bo hands ingest-service to Cy. supersede writes the new fact, closes the old one by setting its valid_to, and records a SUPERSEDES edge between the two versions. Nothing is deleted. Ask the same question again and the answer is Cy, because recall returns only facts that are current.

4The model proposes a write

The user says: Remember this: the ingest-service must not be deployed during the postgres-primary vacuum window. The model calls the remember tool. The server does not write; it parks the call and waits for a decision. Approve to store the fact with writer glm-5.3-flash, or decline to send the model a refusal and let it finish its answer.

5Time travel

Every row carries two intervals: valid time, when the fact was believed true, and transaction time, when the database knew about it. as_of(t) filters on both, so a read at day one still returns Bo as the maintainer even though that row is closed now. This step needs no model. Pick a point on the timeline to re-run recall_2hop for ingest-service and for Ada.

6Provenance

provenance(id) walks the SUPERSEDES chain from a memory back to its first version and collects the episodes and writers along the way. For the current maintainer fact that is two versions, two episodes and two writers. This is how an answer is traced back to the handover note it came from. This step needs no model.

Recall arms

recall fuses up to three arms with reciprocal rank fusion. The text arm is BM25 over the query words. The graph arm is a two-hop walk from the seed entity, newest fact first. The vector arm is inactive here because this demo stores no embeddings. A blank cell means that arm did not find the row.

Model

GLM 5.3 Flash via OpenRouter, with two tools: recall (runs at once) and remember (waits for a person). The model's reasoning_details are passed back unmodified on the next request. Tool results and reasoning are collapsed; open them to read the raw text.
